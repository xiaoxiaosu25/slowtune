# 歌曲资料库方案

版本：v1.0 · 2026-10-17

当前基础：新模型已接入网页收藏、歌单、歌曲与版本编辑、榜单上下文、新队列、播放选择、设置备份、来源批量预览、维护、合并／移动及 B站同步。全部资料写入口使用同一产品服务；被替代的资料、维护和同步实现及公共资料库依赖已移除。已有模块接口见[架构与数据](../开发/架构与数据.md#独立歌曲资料模块接口)。开发期通过重建开发库采用新模型，不维护历史迁移、旧客户端、旧接口、旧备份或旧队列兼容。

自动整理已有「生成整理建议 → 按需查看 → 人工采用」的单曲入口，批量和待整理筛选仍按实际需求扩展。歌词已接入网易云／LRCLIB、候选预览与人工选用、逐行显示、导入、独立偏移和前奏提示。隔离回归、真实来源、实体设备与发行包分别验收，方法见[验证规范](../开发/验证规范.md)；当前接入不代表完整发行验收已经完成。

## 1. 已确认方向与模型

收藏、歌单和资料围绕固定歌曲身份组织，标准歌名与歌手允许人工修改。榜单原始歌名、歌手直接作为歌曲资料，视频原标题属于播放版本。每首歌曲可有多个来源版本、一个可空默认版本，歌单成员可固定版本。歌词按具体版本的确切来源保存选择和偏移，同歌不同来源不共享时间轴。

日常入口保持简单：普通来源直接点播或收藏，单版本继续使用同一歌曲模型，不增加启用多版本的步骤。需要管理其他版本时，通过「归入歌曲」收进「歌手 · 歌名」，首个版本默认播放，后续只追加版本。单版本行不常驻默认来源说明，多版本才显示数量入口；固定成员保留标记，版本固定及其他管理操作按需展开。多版本是一层来源索引，不让资料编辑或重复的元信息获取阻塞已有来源点播。

契约维护于 [song-library-types.ts](../../server/song-library-types.ts)，身份与播放选择规则维护于 [song-library-policy.ts](../../server/song-library-policy.ts)。

歌曲保存固定 ID、生效资料、封面、内容类别、字段来源与人工保护、原始资料、别名、默认版本及整理状态。同名不构成同一作品的证据；合集、串烧独立保留。

版本保存固定 ID、所属歌曲、确切来源、人工版本名、类别与演唱者，以及来源原标题、上传者、封面、时长、来源页面与可用性。B站须在创建前取得 BV＋cid，YouTube 使用视频 ID。临时媒体地址、凭据和租约不进入资料或备份。每个用户空间中一个确切来源只归属一个版本和一首歌曲；不同来源同名不自动合并。

收藏有固定 favoriteId、收藏时间与独立顺序，同歌只收藏一次。重复收藏不改变时间和位置，新收藏追加到末尾。歌单成员有独立 entryId、顺序、时间与可空固定版本，允许同歌重复。固定版本须属于成员歌曲。排序提交完整成员排列并核对修订。

桌面手动封面以快照可选 `desktopFavoritesCover` 与歌单可选 `desktopCover` 保存，值为浏览器重新编码的 512×512 JPEG data URL，字符串最多 512 KiB。`set-playlist-cover` 编辑携带 `targetId` 和 `image`，null 删除手动封面；仅桌面 HTTP 路径接受此编辑。图片独立于歌曲身份和成员，排序、移除及歌曲更新不联动，手机保留自动封面展示。选歌曲图片的接口仅读取目标当前成员已保存的桌面封面，限定来源图片域名、格式、8 MiB 正文、12 秒及四个并发请求，不跟随重定向或传递账号凭据。

成员本地保留意图与同步贡献分别管理。同步贡献和映射关联账号、同步关联、具体成员与 BV，保留确切版本／分 P。不再设历史归属未知状态或历史同步恢复流程。

## 2. 榜单、入口与资料保护

ChartSongContext 保存榜单来源域、原始歌名与歌手、可获得的上游歌曲 ID，以及榜单种类、期次、排名、来源页和封面，贯穿搜索、播放与保存。不能从当前页签或视频来源猜测榜单来源。

目录身份优先使用来源域与上游歌曲 ID，否则使用来源域、原始歌名与歌手集合。仅作 NFKC、Unicode 小写及空白规范化，保留标点、版本词与繁简体；歌手去重后固定排序。期次、种类和排名不参与身份。跨来源同名先给候选，关联冲突时明确选择。

人工修改优先于已确认目录资料、可靠提取与原标题回退。保护按字段生效，改歌名不锁住歌手；自动整理只提供建议。来源刷新只改版本事实与可用性，不覆盖歌曲人工资料。

整理最小闭环在歌曲窗口中按需运行，候选仅来自所属歌曲的已存目录资料、来源歌手信息和标题提取；预览有界、会话所有且到期，不写聚合或备份。人工选择候选及字段后，仍由同一资料服务按修订提交，只修改选定的歌名／歌手并标为人工保护与已整理。歧义分别展示，不按同名匹配其他歌曲；合集、串烧保留，版本身份、默认、固定成员和同步映射不变。保存与播放不触发建议生成。

标题提取不把技术标签、歌词／字幕说明当作歌手；书名号后没有明确分隔符的文本不推断为歌手。无法确认歌手时仅建议歌名并提示核对，来源已存歌手资料仍可作为依据；采用歌名不会保护或修改未建议的歌手字段。

榜单歌曲可在没有来源时收藏，显示待选择版本。普通来源保存时复用确切归属或创建待整理歌曲；明确添加第一个版本设为默认，备用版本不改默认。纯播放不隐式收藏或保存永久默认。

资料列表以歌曲生效资料为主，版本标签和原标题用于辨识。来源搜索、发现与作者内容继续表示原始来源，点击具体来源播放所点版本。上传者、评论、时长与音质随当前确切版本读取。

## 3. 播放选择与切换

选择顺序：本次明确版本 → 歌单固定版本 → 歌曲默认版本 → 无永久选择时临时搜索。已选版本失效或关闭时明确报告，不静默换成其他版本。网络、鉴权与限流问题不标永久失效。

队列每次入队有独立实例 ID。歌曲、版本、来源与队列实例身份分别维护。修改默认不打断当前声音；跟随默认的成员下次选择读取新默认。改名不重建队列、不重启音频、不重置音量、倍速或睡眠。

切换分为准备与提交：

1. 独立准备确切来源、计划与租约，保留当前声音、展示及队列。
2. 提交前核对切换代次、当前队列实例、目标、来源启用状态与最新播放意图。暂停、下一首、停止、移除、较新切换及睡眠到期均须正确使旧准备失效。
3. 对同一队列实例从头提交，不继承不同版本的进度；顺序、随机历史和睡眠计数保持。
4. 提交前失败／取消释放未采用计划并保留现场；提交后媒体失败显示新版本错误，提供重试和手动切回，不自动改默认。同一队列项失败重试继续已提交的具体来源、失败位置和最新暂停意图；重新选播及显式版本切换仍从头播放，浏览器恢复队列保持静默。验收要求见[验证规范](../开发/验证规范.md#真实来源验收)。

当前公共接口可以支撑受控切换，无需预先升级公共包。产品接入须独立保存已提交的确切来源，仅提交时更新资源别名，并处理桥接最多 64 个来源的缓存。验证入口与接入边界见[验证规范](../开发/验证规范.md#播放器切换验证)。

浏览器队列直接采用新格式，不读取、转换或恢复旧格式；不自动发声。

## 4. 同步、事务与服务边界

映射按用户空间、账号、关联、具体成员与 BV 保存，远端按 BV 集合投影，同一收藏夹内多个成员和 P 仅保留一个视频。引用计数限定在账号和该关联内。

映射须明确建立，不从默认版本重新推导。增加备用、改资料与改默认不自动修改远端。远端删除解除当前关联的贡献与映射，保留全局歌曲、版本及独立本地成员；不得下一轮从保留成员重新生成映射。已确认成员只有在没有本地贡献与剩余同步贡献时才因远端删除移除。

歌曲、版本、成员、顺序、贡献、映射和待处理事件由同一产品服务在同一用户空间、同一 SQLite 事务中提交。远端与 SQLite 无跨平台原子事务：发送前持久化意图，重试重新读取当前关系、账号和来源代次，取消被后续操作取代的意图。

新接口使用 /api/song-library，复用现有会话、同源和业务请求头鉴权。用户空间由服务配置决定，不由请求 JSON 指定。编辑按当前修订提交；冲突返回当前修订并保留页面草稿。网页进入不等待资料库读取，后台先检查轻量修订号，变化后才取全量；已保存的确切来源只修改关系，不隐式刷新来源事实。不需要旧客户端能力协商或旧接口桥接。

开发数据库直接重建初始化新结构，不执行迁移、不保留旧表或长期双写。验证显式指定隔离开发路径，不改日常实例。现有链路按阶段替换，完成替换后删除被替代实现、废弃入口与无用依赖；不把现有运行实现包装为新模型兼容层。

合并、移动与完整删除使用影响预览，在事务中处理默认、固定成员和同步映射。合并保留目标歌曲、歌单成员与重复次数；两首均已收藏时保留目标收藏身份，时间取较早、位置取较前，其他成员相对顺序保持。

## 5. 新备份

仅支持 format: "slowtune-library"、version: 1。所有嵌套对象严格解码，拒绝未知字段、非法来源、运行时数据和错误关系，导出执行同样校验。不存在旧格式转换入口。

快照上限为 **64 MiB（67,108,864 字节）**。文件、粘贴、HTTP 流式读取、UTF-8 编码／解码统一限制，不能先无界解析再检查。HTTP 直接发送快照，避免嵌套字符串转义造成限额不一致。

备份完整保留歌曲人工资料、原始资料、别名、版本、默认、收藏身份／时间／顺序、歌单与成员身份／顺序、固定版本和目录关联。账号权限、远端基线、待确认操作、凭据和媒体不属于可移植备份。

手动收藏／歌单封面图片属于可移植快照，计入同一 64 MiB 总限额。追加导入时，目标尚无手动封面可采用导入图片，两边都有且不同则报告封面冲突并阻止提交；缺少封面字段不清除已有图片。替换按备份完整恢复，缺少字段即恢复自动封面；音视频文件仍不进入备份。

导入先生成有界、会话所有且到期的预览，提交再核对修订。追加遇到身份或资料冲突阻止提交，不覆盖人工资料；已有收藏不重排，新收藏按备份内部顺序追加。替换按备份顺序完整恢复，明确显示移除范围。

导入的全部可见成员产生本地保留贡献，不自动恢复远端删除权限。受影响现有关联暂停，待核对当前映射与远端差异；映射失效及待处理事件在同一事务中处理。这是当前导入的副作用检查，不是历史同步归属恢复。

## 剩余任务与验收

| 顺序 | 剩余范围 | 完成条件 |
| --- | --- | --- |
| 自动整理扩展 | 首个单曲最小闭环已接入；待整理筛选与批量建议按实际需求继续，不自动扩展来源或全库扫描 | 沿用有界候选、人工采用和字段保护，歧义不自动合并，播放与收藏不等待整理，不要求用户清空待整理列表 |

主要链路与既有功能闭环共同构成首个完整产品替换。模块、宿主和浏览器回归使用新契约，覆盖批量部分失败、影响预览、并发取消、重复成员／分 P 的 BV 计数、远端删除后的贡献保留、发送结果不确定和执行器重启。隔离开发库按显式入口初始化或重建；已有日常实例更新沿用其数据库、设置和账号资料，不引入历史迁移或客户端兼容。真实同步另行确认操作范围，隔离测试不包含对日常实例的切换。

自动整理的建议采用继续通过同一资料服务提交；歌词复用稳定来源／版本身份，普通听歌不因歌词建立永久收藏或版本。歌词正文和缓存不并入每次读取的完整歌曲聚合。桌面首版可独立复用当前页面与服务，不以自动整理或歌词完成为前置，不另建桌面资料模型。

当前网页、备份、维护和同步使用同一新模型状态，宿主将新结构保存在 `database + '.song-library.sqlite'`，不读取、转换或双写原库。浏览器只读写 v3 新队列，不读取 v1／v2。批量预览保留成功项并显示失败原因，部分成功须明确缩小提交范围；检查来源只刷新版本事实，合并、移动与完整删除均先预览影响，再按修订提交。

同步执行器发送远端请求前重新读取当前映射、关联状态、资料修订和账号代次，确认意图仍有效后执行，并通过事务确认结果。默认版本变化不重建已确认映射；暂停保留有效意图，备份导入使受影响关联等待核对。新建远端收藏夹结果不确定时只核对已有结果，不自动再次新建。后台每 2 分钟检查已启用关联，每轮有界导入新增视频，设置提供具体成员／版本的映射预览、暂停、恢复与解除关联。

## 7. 验收标准

验证覆盖严格结构与关系、来源唯一与具体 P、字段保护、排序、用户空间、CAS 并发、取消／异常回滚、待处理事件、追加冲突、替换恢复和 64 MiB 边界。播放器、网页、真实来源、实体设备分别记录。

实现变化直接更新[架构与数据](../开发/架构与数据.md)、[接口说明](../开发/接口说明.md)、[运行维护](../运维/运行维护.md)和本文的当前状态。测试方法统一维护于[验证规范](../开发/验证规范.md)，不另外累积阶段流水；编译通过不代表真实播放或同步已经验收。
