# 验证规范

本页说明贡献者如何运行测试。测试源码和小型合成夹具随仓库维护，执行产生的报告、截图、日志、数据库及浏览器资料保存在隔离输出中。支持范围见[当前限制](../产品/当前限制.md)。

## 环境与构建

需要 Windows、满足 [package.json](../../package.json) 的 Node.js，以及 npm 安装的开发依赖。浏览器测试默认使用已安装的 Microsoft Edge；可通过 `MUSIC_APP_BROWSER` 指定兼容的 Chromium 可执行文件。Electron 用例使用 npm 安装的 Electron；它们需要可用的 Windows 桌面环境。

```powershell
npm ci
npm test
```

`npm test` 先通过 `pretest` 完成普通构建和桌面专用构建，再串行运行有效的全部顶层用例，避免浏览器与原生窗口争用。普通测试从 `dist/` 导入；桌面宿主测试使用 `scripts/workspace-paths.mjs` 解析的桌面构建。构建失败会阻止测试启动。需要真实窗口、浏览器或本机工具的用例具有相应环境前提，不应仅凭文件名是否含 `ui` 判断。

源码归档测试使用真实 tar 工具校验中文及其他 Unicode 路径。Windows 优先使用 Git 附带的 GNU tar，避免系统工具受 ANSI 代码页影响；可通过 `MUSIC_APP_TEST_TAR` 显式选择支持 UTF-8 PAX 的 tar。解压时由 Node 解开 gzip 并把 tar 数据送到标准输入，保留文件名与内容的完整断言。

## 按修改范围选择测试

```powershell
# 文档、公开源码与交付范围
npm run docs:check
node --test tests/documentation.test.mjs tests/desktop-lyric-source.test.mjs

# 已构建后的服务测试示例
npm run build
node --import ./tests/helpers/isolated-build.mjs --test tests/song-library.test.mjs tests/song-library-sync.test.mjs

# 浏览器测试示例
node --import ./tests/helpers/isolated-build.mjs --test tests/playlist-cover-ui.test.mjs
```

选择受影响模块及其调用链的测试。歌曲、版本、导入、同步与维护变更覆盖事务、修订竞争、取消和关系保护；播放变更覆盖队列、资源准备／提交、失败恢复与迟到结果；桌面变更覆盖生命周期、持久化和有限 IPC。既有移动端用例只用于回归保护，不能据此恢复移动端开发。

`desktop-library-layout-ui.test.mjs` 在 1280 × 720 检查歌单首屏可见歌曲数量、管理菜单与弹窗返回、单行歌词展开／收起、播放不中断、浮岛／长条布局及队列打开时的窄桌面宽度；并用窄屏回归保护原有歌单入口与双行歌词。

`sleep-timer-ui.test.mjs` 将实际睡眠面板、播放装配和固定播放器接入受控原生音频，验证规则互换、草稿与快捷设置同步、输入校验、自然完播与手动定位的计数区别、暂停与取消、到期阻止迟到起播，以及停止释放资源和独立桌面退出请求。退出请求使用宿主替身，不代替 Electron 的实际退出验收。

Windows CI 的 `source` 检查执行依赖审计、公开文件边界和普通构建，再通过 [测试分组](../../scripts/test-groups.mjs) 运行 `core` 与 `browser` 回归；`desktop` 检查先执行 `npm run pretest`，再串行验证原生宿主、服务生命周期、持久化、损坏状态恢复、重启和控制接口。两项检查是合入条件，选定用例不等于全量测试或实体设备验收。CI 不生成桌面分发包。

本地可运行 `node scripts/test-groups.mjs core` 检查资料、来源、歌词与持久化；`browser` 检查播放、版本切换、进度、错误恢复和现有移动端回归；`desktop` 检查原生宿主、重启、状态恢复与退出。所有分组先运行 `npm run build`，桌面组另运行 `npm run desktop:build`；浏览器与原生用例串行执行，避免窗口和计时争用。分组是关键回归集合，不替代 `npm test` 全量入口；新增关键流程须同时维护清单。

`song-library-worker.test.mjs` 使用独立文件 SQLite 验证跨线程修订、失败回滚、取消、排队上限和退出；`desktop-runtime-ui.test.mjs` 验证模块加载失败重试、桌面管理入口不存在额外的未加载静态依赖、跨管理界面复用成功重试的模块、页面异常后的持续播放，以及进度更新不重复渲染应用外壳。定时器可推进证明宿主未被整段计算占用，不代表真实来源延迟或实体设备验收。

只运行桌面相关用例时，先准备两种构建；需要显式选择桌面构建时使用现有重定向入口：

```powershell
npm run pretest
$env:MUSIC_APP_TEST_BUILD = node --input-type=module -e "import { desktopBuildDirectory } from './scripts/workspace-paths.mjs'; console.log(desktopBuildDirectory())"
node --import ./tests/helpers/isolated-build.mjs --test tests/desktop-host.test.mjs
Remove-Item Env:MUSIC_APP_TEST_BUILD
```

## 隔离与输出

- 使用独立配置、SQLite、端口、浏览器上下文和 Electron 偏好目录。测试不得写入日常实例。
- 通用测试使用合成账号与受控上游；真实账号、真实远端写操作和长期播放需要显式指定对象、权限和环境，不能加入普通 CI 默认入口。
- 浏览器可执行路径由 `tests/helpers/browser.mjs` 统一选择；测试输出按 `scripts/workspace-paths.mjs` 解析。独立克隆的可再生成输出位于 `local/`。
- 日志、截图、视频、覆盖率、临时库和 profile 不提交 Git。CI 需要共享结果时，先脱敏再保存为有保留期限的工作流附件。
- 检查完成后确认测试进程已经退出，再清理明确可再生成的隔离输出。日常 data、固定样本和恢复备份有各自保留要求。

## 结果范围

类型检查和构建证明当前输入可编译；单元、服务、浏览器和 Electron 测试证明各自受测分支。受控音频、模拟电源事件、原生窗口状态或合成凭据不能代替实体设备、真实来源、跨用户恢复或发行包验收。

PR 写明实际命令、结果、环境与未覆盖项。规范正文维护当前方法，不累积测试数量与历次执行流水。公开附件去除 Cookie、访问码、控制密钥、账号身份、私人路径和媒体签名地址。

仅在维护者明确生成发行候选包后，将 ZIP 解压到新的隔离目录，使用 `npm run desktop:verify -- <解压后的SlowTune.exe绝对路径>` 检查其独立运行行为。该检查从 PATH 移除开发工具，使用独立资料目录，覆盖首次启动、会话恢复、合成音频的播放／暂停／跳转／继续、资料写入与重开、重复启动和退出停服。合成音频仅验证打包后的播放链路，不代表真实平台或实体声卡验收；普通源码检查不需要执行桌面打包。

发行前还需在另一份新解压、没有 `data/` 的副本上追加 `--portable-data`，检查 EXE 同级默认资料目录；该模式拒绝已有资料目录，不修改日常实例。源码开发的旧资料接入保护仅作用于开发启动，不阻止免安装包建立自己的资料目录。
