## 环境与构建

需要 Windows、满足 [package.json](../../package.json) 的 Node.js 和开发依赖。浏览器默认使用 Edge，`MUSIC_APP_BROWSER` 可指定兼容 Chromium；Electron 测试需要交互式 Windows 桌面。

```powershell
npm ci
npm test
```

`npm test` 通过 pretest 构建普通服务和桌面输出，再串行运行全部顶层用例。普通测试使用 dist，桌面构建由 `scripts/workspace-paths.mjs` 解析。

源码归档测试需支持 UTF-8 PAX 的 tar。Windows 优先 Git 附带 GNU tar，可用 `MUSIC_APP_TEST_TAR` 指定；Node 解开 gzip 后将 tar 送入标准输入，检查 Unicode 路径与内容。

### 移动 Web 回归

覆盖 320／360／390／430px、568 × 320 和 667 × 375、深浅主题、长标题、48px 触控及安全区避让。

- 导航与长流程：搜索、歌单、设置、榜单、作者、合集和投稿往返保留分页、滚动与草稿；完整播放展开／返回沿用同一音频实例。欢迎及设置页检查软键盘、预览保存、会话撤销和失败重试。
- 歌曲与来源：核对各页字号、留白、横向操作、发布时间及作者／来源。标题与封面直接播放，单次点击只发起一次准备；更多保留原视频标题，查看详情不重启音频。多 P 保留唯一主动选择入口，默认播放当前 P，已保存歌曲标题仅用于身份对应明确的来源；桌面既有选择流程保持可用。
- 发现与榜单：推荐封面／列表先显示六首，关注摘要先显示四首；展开、收起和切视图重新确认实际可见内容，收起后栏目标题可见。带文字的批量播放按钮保留 48px 触控区，播放范围与展示范围分别验证。榜单类型、信息展开及缓存切换可用，320px 下标题、数量和播放按钮互不遮挡。
- 音乐库与关注：检查收藏拼贴的缺图、少量封面、自建歌单手动封面与宽幅入口；管理面板可进入维护和导入／导出。关注同时检查推荐页摘要及列表／封面浏览，操作面板可添加关注、切换视图及批量加入歌单。
- 播放与短屏：空队列使用 48px 聆听提示，开始播放或恢复队列后使用 72px 迷你播放器；歌词、版本和播放控制可达。封面与列表图片尺寸分别核对，搜索只保留一个粘贴链接入口。

### 电脑交互与共享搜索

- 推荐反馈：B站与 YouTube 分别覆盖旧批次、读取失败、空内容、登录失效、重试与取消。已有歌曲和音频保留，失败归属栏目；详情 Esc 返回入口焦点，成功后清除异常状态，移动布局保留原反馈入口。
- 菜单交互：覆盖歌曲行／封面／榜单／队列／侧栏歌单与更多入口一致；检查窗口四角、短窗、深浅主题、滚动关闭、输入框原生编辑、菜单键／Shift+F10、方向键／Home／End及 Esc 焦点返回。菜单关闭不误关搜索弹窗，切换移动布局保留原更多面板。
- 队列操作：空队列入队不自动起播，随机模式优先下一首，移动原条目不复制，重复歌单成员和固定版本正确。延迟点播时，单曲、来源及整份歌单入队保留原点播；先移到下一首再移到队尾，按新顺序播放并保留条目身份。
- 搜索：覆盖电脑及 320／390px，四种视频排序重新查询且不沿用旧游标，自动匹配默认规则保持。用户昵称、排序、直接分页及投稿往返保留上下文；用户搜索换词后切回视频更新歌曲匹配信息，未换词保留原信息。关注失败保留原状态，迟到请求不覆盖新查询，风控显示失败与重试。

### 歌词与播放版本

- 候选搜索：打开时一次查找，来源筛选不重复请求；核对时长差、原标题填入、默认关键词及手动草稿。
- 全文预览：宽窗默认预览、点选保留列表位置、两侧独立滚动及固定采用；窄窗／手机返回保留位置和焦点，搜索展开、导入及底栏可用。迟到预览不覆盖新选择，预览不取消渐进搜索或修改当前歌词；关闭保存中的窗口后，完成结果不重开窗口。
- 播放版本：独立弹窗检查试听、设默认、确切来源身份及失败保留原播放。
- 时间校准：检查 50ms 步进、拖动预览、归零／撤销、显式保存、关闭撤销和修订冲突恢复；沿用同一音频实例与来源，悬浮及沉浸歌词共享偏移。
- 沉浸阅读：检查侧边图标、短窗、闲置显隐及控件聚焦。实际播放跨换句检查中间帧：当前句／邻句尺寸比 1.5、字重有中间态、整段平稳居中并收敛；拖动或暂停定位不播放跨段动画，普通 LRC 不产生逐字遮罩。系统减少动态与独立偏好的覆盖关系正确，切换保留渲染器和音频。
- 悬浮歌词：检查长句随媒体时钟移动、暂停／拖动定位、真实逐字变色、末句与偏移、单双行位置稳定及减少动态。窗口高度、锁定穿透、选项展开与底边锚点另运行 `desktop-app` 原生测试。

动效证据可设置 `MUSIC_APP_MOTION_VIDEO=1` 录制，本机须已安装 Playwright FFmpeg；常规测试不依赖录屏组件。

### 整库操作与播放延迟

构建后执行 `node scripts/verify-library-playback-performance.mjs`，使用独立 SQLite、合成歌曲／版本／映射和只读远端夹具；Edge 持续解码流式 PCM，同场测量导出、同步状态／预览／执行和导入预览。输出请求延迟、服务事件循环、事务耗时、媒体发送间隔及实际媒体事件；事务耗时不单独证明锁等待。脚本不接入日常资料或真实账号，不提交远端修改。

`MUSIC_APP_LIBRARY_PERF_SONGS` 可指定 100–10000 首；`MUSIC_APP_LIBRARY_PERF_OUTPUT` 选择新的隔离输出，默认位于测试运行目录；`MUSIC_APP_TEST_BUILD` 可选择另一个独立服务构建。比较须保持数据规模、固定依赖与脚本相同，并确认请求确实进入桌面路径。结果用于定位热点，不能由短时无错误推导长期无中断。

### CI 与分组执行

Windows `Source checks` 的 source 执行 `deps:check` 依赖关系检查、依赖审计、公开范围、普通构建及 core／browser；core 包含固定制品及对应源码的 vendor 检查。desktop 执行 pretest 和宿主生命周期回归。实际清单见[工作流](../../.github/workflows/check.yml)。

分组脚本不会构建：

```powershell
npm run build
node scripts/test-groups.mjs core
node scripts/test-groups.mjs browser
npm run desktop:build
node scripts/test-groups.mjs desktop
```

core 最多四个文件并发，browser 和 desktop 串行。分组是关键回归集合，不替代 `npm test`；新增关键流程同步 [test-groups.mjs](../../scripts/test-groups.mjs)。

只选桌面宿主用例时可显式设置构建：

```powershell
npm run pretest
$env:MUSIC_APP_TEST_BUILD = node --input-type=module -e "import { desktopBuildDirectory } from './scripts/workspace-paths.mjs'; console.log(desktopBuildDirectory())"
node --import ./tests/helpers/isolated-build.mjs --test tests/desktop-host.test.mjs
Remove-Item Env:MUSIC_APP_TEST_BUILD
```

## 隔离与输出

- 每项测试使用独立配置、SQLite、端口、浏览器／Electron 资料，不写日常实例。
- 普通回归使用合成账号、受控上游与音频；真实远端写操作需明确对象、权限和环境。
- 输出路径由 `scripts/workspace-paths.mjs` 解析；报告、截图、数据库及 profile 不提交，CI 附件脱敏并设置保留期。
- 测试进程结束后才清理明确可再生成输出，不清理日常 data、固定样本或恢复备份。

## 结果范围

构建证明可编译，受控用例证明受测分支；真实来源、实体声卡／媒体键、手机键盘／系统行为、跨用户恢复及长期播放单独验收。PR 写实际命令、环境、结果与未覆盖项，正文不累积执行记录。

明确要求发行并已有候选 ZIP 后，解压到隔离目录，执行 `npm run desktop:verify -- <SlowTune.exe绝对路径>`。检查无开发工具 PATH 下的首次启动、会话、受控播放、资料重开、重复启动和退出。

再用没有 data 的新解压副本追加 `--portable-data`，检查 EXE 同级默认资料。该模式拒绝已有资料，不操作日常实例；程序包和实机检查不由源码测试替代。
