# 验证规范

本文维护当前检查方法、测试职责与验收要求，不保存历次执行流水、旧构建结论或历史截图。产品范围见[产品功能](../产品/产品功能.md)，数据模型见[歌曲资料库方案](../计划/歌曲资料库方案.md)。每次修改按受影响范围重新验证。

## 检查层次

| 层次 | 典型检查 | 可以证明 | 仍需另行验证 |
| --- | --- | --- | --- |
| 静态源码 | 配置、路由、类型、分支与持久化字段 | 当前实现的逻辑与装配状态 | 上游可用性与设备表现 |
| 类型与构建 | TypeScript、服务编译与 Vite 构建 | 当前依赖和源码可构建 | 实际播放与发行包 |
| 单元与服务回归 | Node test runner、隔离服务 | 受测输入、事务、协议与异常行为 | 全部系统与真实来源 |
| 浏览器回归 | Edge／Chromium、受控音频 | 页面操作与浏览器播放行为 | 实体设备与系统媒体控制 |
| 真实来源 | 隔离服务、实际网络和账号 | 所选来源、账号、音轨与时段的结果 | 其他来源、地区与长期运行 |
| 发行包与设备 | 桌面包与真实设备 | 对应包和设备场景 | 其他平台的等价行为 |

## 命令与隔离环境

环境要求见[依赖清单](../参考/依赖清单.md)。测试使用 Node test runner，服务和浏览器用例需要配套构建；部分浏览器用例使用本机 Edge 和固定端口，执行前核对路径与占用。

```powershell
npm run build
npm test
npm run desktop:build
```

服务和浏览器测试默认使用根目录 `dist/`。需要测试指定构建时设置 `MUSIC_APP_TEST_BUILD`，并通过 `tests/helpers/isolated-build.mjs` 将模块导入和子进程重定向到配套构建。执行期间仍保留测试解析所需的根目录构建。

```powershell
$env:MUSIC_APP_TEST_BUILD = node --input-type=module -e "import { desktopBuildDirectory } from './scripts/workspace-paths.mjs'; console.log(desktopBuildDirectory())"
node --import ./tests/helpers/isolated-build.mjs --test tests/vendor.test.mjs tests/desktop-host.test.mjs
```

验证不得写入日常实例。使用独立 SQLite、随机端口、浏览器上下文和 Electron 偏好目录；涉及真实账号或远端收藏操作时明确限定对象与操作范围。移动端用例只用于保护既有行为，不恢复移动端开发。

验证完成后按需清理隔离构建、测试资料、浏览器 profile、截图与日志，保留需要的当前桌面构建；独立克隆使用 `local/desktop-build/`。根目录 `dist/` 是服务开发和测试的临时输出。清理前确认测试进程已经退出，目标确属可再生成的隔离输出；不操作实际使用的资料目录。

## 播放器切换验证

`song-version-switch.test.mjs` 使用固定公共播放器、队列和来源桥接，通过本地 PCM 验证版本准备与提交。准备完成前保留当前音频；仅提交时更新确切来源；失败、取消和迟到结果必须释放未采用计划，保留当前队列与资源。

`chart-playback-queue.test.mjs`、`playback.test.mjs` 检查点播插入、重选复用、默认与固定版本、随机历史、自然接续及静默恢复。桌面批量播放使用惰性准备，局部失败按顺序跳过，整体网络或身份错误停止。

`playback-retry.test.mjs` 检查媒体失败后的同资源重试，保留失败位置、确切来源和最新暂停意图；覆盖准备失败、取消、下一首、连续重试与迟到租约释放。重新选播和显式版本切换从头开始，恢复浏览器队列保持静默。

`playback-performance-ui.test.mjs`、`desktop-playback-optimization-ui.test.mjs` 检查请求复用、歌词不阻塞起播、准备期间原音频继续与真实频谱。`desktop-playback-transitions-ui.test.mjs` 检查不同播放入口间的错误清理与准备任务归属。

`desktop-continuity.test.mjs`、`desktop-playback-performance.test.mjs` 覆盖在途共享、独立取消、身份与代次隔离、有界预取、消费／丢弃成本及恢复上限。受控延迟只能证明请求数量与等待关系，不能作为真实上游起播耗时。

## 推荐与来源验证

推荐相关用例覆盖偏好修订、批次、候选筛选、账号隔离、缓存失效与不足补齐。`bilibili-desktop-recommendations.test.mjs` 检查新旧分区冲突、音乐子分区与非音乐内容排除，手机路径只做回归保护。

`search-preferences.test.mjs`、`desktop-match-precision.test.mjs` 覆盖歌名、歌手、版本、时长、候选顺序与错误传播。标注夹具只说明受测版本决策，不代表整体准确率。

`search-playback.test.mjs` 检查有界音频前缀、容器特征、截断、超时与取消；前缀通过不能证明整曲完整或浏览器解码成功。`desktop-media-policy.test.mjs` 检查桌面连接、首字节和空闲预算以及既有手机政策；`desktop-youtube-reuse.test.mjs` 使用受控工具进程检查桌面短期复用与代次隔离。

发行包验证需要实际生成的分发 EXE／ZIP。已有交付包可通过 `npm run desktop:verify -- <SlowTune.exe绝对路径>` 验证无源码运行时依赖、首次建库、会话、重复启动、关窗停服和资料重开保留。源码构建或隔离 Electron 测试不等于新机器安装通过。

偏好检查先比较大队列和频繁设置修改的事件循环延迟、提交耗时及实际写入次数；可用超出产品 500 项上限的 5,000 项合成资料施压，这不扩大产品队列容量。分别验证合并窗口内最后修改、写入进行中的修改、删除、磁盘失败后最后成功文件不变、内存最新值保留、重试、立即退出和重开。队列、窗口状态和欢迎图共用串行原子写入，Promise 完成应表示对应修订或包含它的较新修订已落盘，不能只证明 IPC 已发送。启动读取仍为同步操作，不以写入测量声称所有磁盘操作无阻塞。

状态读取故障分别覆盖真实损坏文件、无效格式和文件位置不可读，权限／磁盘错误码用受控读取器注入；退出末尾故障通过隔离服务删除自身记录时的文件事件，核对此时已卸载播放页，阻断真实临时文件写入并产生新窗口修改。释放失败、确认超时及启动中退出保存失败均检查恢复页的重试退出入口。服务归属不符时应保持服务存活，恢复正确记录后仅停止原服务。这些检查证明受测分支，不代表真实磁盘耗尽、Windows ACL、物理磁盘故障或实体设备退出交互已验收。

完整 data 恢复的本机受控链路已通过上述用例：测试先确认桌面和服务退出再复制，保留原资料；服务上游 fetch 与渲染器外网请求均阻断，只读取合成测试凭据。同用户 DPAPI 可读不代表换机器或用户后账号仍可用。歌单 JSON 导入只恢复其格式包含的可移植资料，不能代替完整目录恢复；不测试或实现历史开发格式迁移。

置顶排查使用不加载慢听的普通／透明 Electron 窗口，分别在 Playwright 和直接启动下观察创建、显示、层级切换、焦点、锁定／解锁和最小化；用 `getNativeWindowHandle()` 定位 HWND，确认 PID、有效性及 `WS_EX_TOPMOST`，同时读取任务栏样式，探针只读原生状态。当前任务栏非置顶时，默认 `floating` 可稳定使两个状态均为 false，显式 `pop-up-menu` 恢复为 true；产品已使用该层级，实际产品回归通过。焦点检查记录 Electron 的 `focus()` 请求与 Win32 前台 HWND；自动化下 Electron 可报告主窗口 focused，而系统前台仍属于其他窗口，因此不将其写成实体前后台切换通过。实现依据及限制见[桌面应用方案](../计划/桌面应用方案.md#剩余任务与完成条件)。不删除或跳过失败断言，不以反复调用或高频轮询代替修复。

首发前仍须按[桌面剩余验收](../计划/桌面应用方案.md#剩余任务与完成条件)执行手动升级／回退、两来源至少 4 小时播放、实体媒体键、实际 Windows 休眠唤醒、浮窗实体交互及干净 Windows 交付／跨用户恢复。升级与新机器验收需要对应版本的候选包。真实鼠标拖动、贴靠和其他应用前置遮挡需独立实机检查；受控剪贴板、磁盘故障、原生置顶位、Electron 生命周期和模拟电源事件不能替代实体设备或发行包验收。

## 真实来源验收

实际使用的配置、数据库和凭据与隔离测试分别管理。构建、隔离测试与项目清理不得重建、恢复覆盖或写入真实资料；真实来源验收应使用明确选定的资料副本与账号，并限定操作范围。

更新或启动核对源码构建、实际服务、窗口加载资源和所选配置一致。数据核对覆盖歌曲完整资料、同步关系、设置、关注、歌词和账号状态；浏览缓存的正常刷新与资料变更分别判断。

真实来源验收明确所选歌曲、确切版本、账号、操作范围与时段；解码时间推进、非零浏览器信号、实体扬声器听感和长期稳定性分别报告。不得用短时恢复或模拟窗口尺寸宣称实体设备或长期使用通过。

## 文档工具检查

`npm run docs:check` 只读检查生成内容、接口覆盖、导航、相对链接和章节锚点。修改生成器时运行 `node --test tests/documentation.test.mjs`，覆盖路由与挂载、新接口契约、动态声明、依赖／命令变化、导航遗漏、确定性和只读检查。

自动检查不能代替语义核对。依赖、功能或文件移除后同步更新权威正文及全部引用，不保留指向旧构建或已删除报告的说明。

## 结果与文档检查

结果写明当前源码与构建、命令、隔离方式、受测范围、通过或失败及未覆盖项，不沿用以前构建的测试数量。不输出访问码、Cookie、控制密钥或签名媒体地址。

验证完成后在交付说明中报告本次结论，规范正文只维护有效方法与要求；不把执行流水、历史报告、截图或旧分发包重新加入仓库。
