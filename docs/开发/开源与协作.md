分发修改版本时保留相关版权与许可，说明修改，并按许可证提供对应源码；网络服务的源码提供义务以许可原文为准。不添加“仅限个人使用”或“禁止商业使用”等与本开源许可冲突的附加条件。平台内容与非官方来源接入说明见[第三方声明](../../第三方声明.md)。

## 公共包及对应源码

三个 `@studio/*` 包由维护者单独维护，慢听通过 `vendor/` 中的本地 npm 安装包引用，对应源码以版本归档随仓库提供。解压和构建步骤见 [vendor/README.md](../../vendor/README.md)。包源码修改以补丁提交，由维护者合入包源码并生成新版本。

更新公共包时一并更新依赖和锁文件、安装制品、对应版本源码、许可证及来源记录，再更新自动生成文档。只整理公开材料不自动升级包版本；不得用平台较新源码冒充慢听当前依赖版本。

构建产生的 `/legal/desktop-lyrics-source.tar.gz` 包含本构建应用源码、构建脚本、锁文件、固定依赖及其源码归档、许可证和上游材料。公开源码输入由 [public-source.mjs](../../scripts/public-source.mjs)统一选择：根目录文件和公开文档逐项列出，实现、测试、素材及许可目录递归收录；发现其中的本地配置或运行资料时拒绝导出。新增公开文档时同步维护清单和导航。所有公开输入仍需人工审查，不在源码目录放私人资料。

## 自动依赖更新

Dependabot 每周为 npm 依赖和 GitHub Actions 提交临时升级 PR。检查与人工审查通过后合入 `main`，随后删除已合并的临时分支。

当前 `@types/node` 保持 24 大版本，匹配 CI 的 Node.js 24 环境；`@vitejs/plugin-react` 保持 5 大版本，匹配当前 Vite 6。Dependabot 暂不提交这两个依赖的大版本升级，补丁与次版本更新继续正常检查。升级 Node.js 或 Vite 时，一并核对并调整 `.github/dependabot.yml` 的限制。

## 仓库边界

- 提交源码、锁文件、配置示例、必要静态素材、许可证及当前固定依赖的交付材料。
- 私人配置、`.env`、凭据、数据库、完整 `data/`、日志、缓存、隔离验证目录和 EXE／ZIP 输出留在本地。配置示例只放示例值。
- 忽略规则不会移除已跟踪文件及 Git 历史中的内容。发现实际泄露时先撤销或更换对应凭据，再决定必要的历史处理；不在普通文档维护中重写 Git 历史。
- 作者工作区路径声明、机器上的协作工具规则和内部项目入口不进入公开快照。公开仓库按 README 直接安装、构建和启动。
- 产品源码、有效测试、公开文档和通用构建／维护脚本在产品 Git 中提交，再通过分支／PR 同步远端。个人执行计划、实例记录和本机排查过程由独立的本地或私有维护资料仓库提交；不依赖“暂时不 push”隔离同一分支中的内部内容。
- 测试报告和截图按需作为脱敏后的 Actions 附件，程序与发行说明按版本作为 Releases 附件；它们不逐次提交源码 Git。公开文档可以包含通用运维和测试方法，内部执行安排不属于公开文档输入。
- 本项目不包含第三方音乐或视频库；歌单与资料备份也不能作为第三方内容传播授权。

`node scripts/generate-notices.mjs` 更新随附许可和应用源码归档。需要导出可审查的公开文件副本时，执行 `node scripts/export-source.mjs <新目录>`；目标必须尚不存在。导出与源码归档共用公开清单，导出另附生成的许可材料，不复制 Git 历史，也不执行提交或上传。这些命令不生成桌面 EXE／ZIP。

## 开发范围

界面和产品适配在本仓库维护，依赖包修复按上述方式更新。当前维护范围为 Windows 桌面，移动端开发暂停。详细规则见[开发约定](开发约定.md)。

安全问题应优先使用仓库已启用的私密漏洞报告；尚无私密渠道时，仅公开描述问题类别并请求维护者提供渠道，不公开利用细节或凭据。
