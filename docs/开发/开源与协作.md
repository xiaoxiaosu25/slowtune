## 公共包及对应源码

公共能力在 Studio platform 唯一维护，慢听固定消费 `vendor/` 制品。公开源码通过 [vendor/README.md](../../vendor/README.md) 所列的版本归档随仓库提供，外部读者无需访问作者的本地平台。源码快照用于交付和修改，不形成第二套正式维护来源。

更新公共包时一并更新依赖和锁文件、安装制品、对应版本源码、许可证及来源记录，再更新自动生成文档。只整理公开材料不自动升级包版本；不得用平台较新源码冒充慢听当前依赖版本。

构建产生的 `/legal/desktop-lyrics-source.tar.gz` 包含本构建应用源码、构建脚本、锁文件、固定依赖及其源码归档、许可证和上游材料。源码生成与打包入口使用显式清单；新添根目录公开文件时同步维护清单。不得把私人资料放进 `src/`、`docs/`、`vendor/` 或 `legal/` 后交由构建自动排除。

## 仓库边界

- 提交源码、锁文件、配置示例、必要静态素材、许可证及当前固定依赖的交付材料。
- 私人配置、`.env`、凭据、数据库、完整 `data/`、日志、缓存、隔离验证目录和 EXE／ZIP 输出留在本地。配置示例只放示例值。
- 忽略规则不会移除已跟踪文件及 Git 历史中的内容。发现实际泄露时先撤销或更换对应凭据，再决定必要的历史处理；不在普通文档维护中重写 Git 历史。
- `workspace.paths.json` 和根目录 `AGENTS.md` 中的 Studio 入口属于作者开发布局。独立克隆按 README 操作；外部贡献不需要复制作者整个工作区或建立新的平台实例。
- 本项目不包含第三方音乐或视频库；歌单与资料备份也不能作为第三方内容传播授权。

现有内部 Git 历史曾跟踪 `local/`、`artifacts/` 下的截图、日志和验证输出，当前跟踪范围已排除这些目录。历史文件内容尚未完整审查，首次公开采用当前源码快照初始化公开仓库，内部历史保留在本机；如需公开原历史，应先另行审查，不直接推送全部内部历史。

当前源码快照通过 `node scripts/generate-notices.mjs` 生成到 `public/legal/desktop-lyrics-source.tar.gz`，包含应用与固定公共包的对应源码和许可，排除 `.git`、依赖安装目录、私人配置、实例资料和本地输出。该命令只整理随附材料，不生成桌面 EXE／ZIP。解压快照后可作为公开仓库的文件来源。

## 修改与反馈

修改前阅读[开发约定](开发约定.md)。界面和产品适配在慢听维护，公共能力修复回平台维护；外部贡献者可附上源码归档中的建议补丁，由维护者同步正式来源并形成新固定版本。移动端开发继续冻结。

提交修改时说明解决的问题、影响范围和实际执行的检查。未执行的检查如实标明，开发预览版不承诺已通过完整实机验收。当前范围优先完善开源规范，CI、完整构建和实机发布验收按后续工作安排推进。

反馈问题时提供应用版本、Windows 版本、复现步骤、预期与实际结果，以及应用内脱敏诊断。公开 issue、截图和附件不要包含 Cookie、访问码、控制密钥、账号二维码、媒体签名地址、完整配置或完整 data。安全问题应优先使用仓库已启用的私密漏洞报告；尚无私密渠道时，仅公开描述问题类别并请求维护者提供渠道，不公开利用细节或凭据。
