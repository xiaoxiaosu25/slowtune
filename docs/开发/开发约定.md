# 开发约定

## 事实依据

- 已实现行为以当前源码、类型、配置、锁文件和脚本为准，开发范围以维护者确认的问题或方案为准。
- 分开说明已接入、独立模块及待实施。构建、受控测试、真实来源和实体设备结论各有范围。
- 文档整理只修改说明及必要引用；业务修改完成对应验证。

## 开发期数据策略

维护 Windows 桌面和现有移动 Web。移动端使用专用组件与样式，共享播放与资料能力，两端分别验证；原生手机端与独立手机运行时另行定范围。

开发库通过明确初始化入口采用当前模型，不实现历史迁移、旧客户端／接口／备份／队列转换或长期双写。替换实现时删除废弃入口、测试及依赖，保留事务、修订冲突、人工字段、来源身份、鉴权、当前格式恢复和同步重试。

测试使用独立配置、数据库、端口及浏览器上下文。重建只处理已校验目标，不修改私人配置、凭据或日常实例。

## 开发产物管理

- 桌面持久资料位于项目根或 EXE 同级 `data/`，服务资料由配置定位；均不属于构建或清理目标。
- 独立克隆桌面构建默认在 `local/desktop-build/`，统一通过 `scripts/workspace-paths.mjs` 解析。Studio 使用项目路径声明。
- `local/`、`artifacts/`、`test-results/`、`dist/`、日志、缓存、数据库及 EXE／ZIP 不提交。清理前确认是本项目可再生成输出。
- 桌面交付构建后清除临时服务 `dist/`，不保留第二份桌面构建。
- `vendor/` 只维护当前依赖制品、对应源码和来源记录，替换依赖时移除失效材料及一次性脚本。

## 文档结构与命名

- [文档导航](../文档导航.md)列出公开文档；产品、开发、运维、参考分别归位，文件名使用清晰中文。
- 每个主题一份正文，使用相对链接引用。产品写操作，界面写布局，架构写机制，接口写契约，验证写方法，运维写步骤。
- 计划放独立维护资料仓库，只保留当前基础、剩余范围、约束和完成条件。完成项写回正文并移出待办。
- 删除过时说明、交接流水、排查过程、旧测试数量、旧工作树状态及旧发行记录，不另建归档副本；历史查 Git／Releases。
- 明确区分 Windows 独立桌面、PC 网页与移动网页；仅指响应式样式时使用桌面／移动布局。
- 长文按职责分节并提供短索引，不复制其他页的完整细节。标题采用稳定主题名，改名同时修复锚点。
- 生成区块不手改；版本和命令不多处手抄。协议字段、制品名和许可原文保留真实名称。
- 示例明确标注；不写入凭据、私人路径、签名媒体 URL、PID 或机器运行状态。

## 自动生成与检查

`npm run docs:generate` 更新以下 generated 区块：

| 正文 | 生成内容 | 事实来源 |
| --- | --- | --- |
| [接口说明](接口说明.md#自动接口清单) | 已装配路由、独立模块和转发规则 | 当前路由声明及服务挂载 |
| [依赖清单](../参考/依赖清单.md) | 产品版本、Node 要求、直接依赖及固定制品 | package.json、package-lock.json、vendor 来源记录 |
| [运行维护](../运维/运行维护.md#npm-命令清单) | npm 命令与实际执行内容 | package.json scripts |

README 下载链接及 vendor 的包／对应源码表随发行或依赖更新人工核对。`npm run docs:check` 只读比较生成区块，并检查导航、本地链接、章节锚点及接口说明覆盖；构建首先执行该检查。

新增接口同时维护方法、路径、请求和响应，失效接口移除说明；动态声明不能静默跳过。接口语义和行为约束仍需人工核对，检查不联网验证上游。

依赖升级先更新包清单、锁文件、安装及 vendor 来源，再生成文档；许可材料使用现有生成脚本。上述工具不启动业务、不读取私人配置或执行接口示例。

## 修改时同步核对

| 变更 | 对应文档 |
| --- | --- |
| 页面与操作 | 产品功能、界面规范、验证规范 |
| 路由、字段、鉴权及错误 | 接口说明、架构与数据 |
| 数据、修订、备份及初始化 | 架构与数据、接口说明、运行维护 |
| 依赖、启动、构建及交付 | README、运行维护、第三方声明 |
| 素材 | 素材与来源、第三方声明 |
| 文件移动或改名 | 导航、引用、公开清单及交付脚本 |

纯文档修改检查链接、锚点、源码对应及差异格式；功能修改按影响范围构建和测试，未覆盖项如实说明。
