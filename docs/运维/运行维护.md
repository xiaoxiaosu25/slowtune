# 运行维护

## Windows 桌面运行

源码目录的 `一键启动.cmd` 打开独立桌面，直接使用已有构建，重复点击唤起原窗口。服务版实例目录的同名入口只启动原配置的服务版。`npm run desktop` 保留前台日志；`npm run desktop:build` 仅构建，`npm run desktop:restart` 有序停止本桌面、重建并打开。构建路径由 [workspace.paths.json](../../workspace.paths.json) 和[开发路径解析](../../scripts/workspace-paths.mjs)维护，Studio 当前为 `studio/local/build/slowtune/desktop`。

仅明确要求时执行 `npm run desktop:package`，生成附普通 Node 的 Windows 免安装目录和 ZIP。完整解压后双击 EXE，自动准备 EXE 同级 data；无需另装 Node、选择配置或输入访问码。当前不包含签名、安装器或自动更新，YouTube 外部工具保持原显式配置。Electron、Chromium 和所附 Node 许可继续随包提供。

源码桌面资料在项目根 data，免安装资料在 EXE 同级 data；均不进入 Git、不受构建清理影响。目录包含 library、preferences.json、desktop-state.json、profile、runtime、cache 和 logs，内部配置位于 instance/config.local.json。更新保留 data；完整备份先退出再复制整个目录。原服务版仍使用原实例，配置不被桌面继承。

关闭主窗口或选择“退出慢听”释放播放并有序停止自己的内部进程；最小化继续播放。启动只有一个主窗口和欢迎页，失败时可重试、打开日志或退出。桌面只监听本机，自动选择可用端口，不接管或停止服务版；归属不符、资料不可写或损坏时明确失败。

退出先保存，再释放播放并使用配套普通 Node 核验归属、控制身份和 PID，停服前后继续等待新修改落盘；超时不强杀未知进程。启动中关闭窗口会等待并清理本次派生的进程；已退出 PID 即视为停止完成。退出失败会说明失败阶段与服务是否已确认停止；播放器已释放或进入停服阶段后显示恢复页，排除故障后点击“重试保存并退出”，退出完成后再打开应用。`MUSIC_APP_DESKTOP_DATA` 指定完整的隔离桌面资料根，仅供显式测试与维护使用。

桌面服务完成请求撤销、音源与租约释放后，主动关闭剩余 HTTP 连接，再等待监听器和进程退出，避免未完成请求或遗留连接卡住关窗。这一步仅用于桌面启动器标记的服务。退出期间控制连接已拒绝或断开时，仍等待所选进程清理完成；控制身份拒绝和归属不符继续报错。桌面停服日志记录开始时间及控制请求／系统信号来源，便于区分播放错误与退出清理。

源码桌面使用鉴权通道提供状态、唤起与退出；记录在 data/desktop-runtime.json，日志在 data/logs/desktop-launch.log。重复打开不重建或终止原窗口。显式重建遇到缺少归属记录的旧桌面时明确报错，不批量结束 Node 或 Electron。

播放器载入前清理 HTTP 资源缓存，保留偏好与会话。偏好由桌面宿主保存到 data/preferences.json，与内部端口分离；浏览器继续使用原 localStorage。首次接入原资料执行 `npm run desktop:adopt`：定位原桌面选择、停服备份、复制当前格式、核对数量，再启用 data；非空目标不覆盖，失败保留原资料与中间目录。初始备份在 data/backups/initial。复制的同步关联暂停，核对映射后恢复；原服务版资料保留。

桌面播放与界面偏好、窗口／歌词状态和欢迎图采用异步 IPC、合并及串行原子写入；正常关窗会等待必要保存。出现“本地设置尚未保存”时，当前修改仍在内存，最后成功文件保留；检查磁盘空间与资料目录权限，点击“重试保存偏好”，保存成功后再退出。失败会拦截正常退出，不要用强制结束代替保存。设置“运行信息 → 复制诊断信息”只将版本、状态和错误分类写入剪贴板，不自动上传；不含私人路径、账号身份、凭据、媒体地址及原始日志。

`desktop-state.json` 不存在时才按首次启动处理。启动页会区分 JSON 损坏、格式无效及读取失败，阻止进入播放器并保护原文件。读取失败先排查目录权限、文件占用和磁盘，再点击“重试”；损坏或无效时用“打开资料文件夹”定位，先保留原文件，再恢复有效备份，或将原文件另行改名后重试以重建窗口与歌词设置。只处理这一状态文件，不清空或合并 data，不增加旧格式转换。“歌单 JSON 导入与导出”只打开歌曲资料备份弹窗，完整 data 恢复仍须完全退出后复制目录。

命令与路径以 [package.json](../../package.json)、[配置定位脚本](../../scripts/instance-path.mjs)和 [scripts/](../../scripts) 为准。主要页面、备份、维护与同步采用新歌曲资料；开发初始化命令仅用于显式指定的隔离库。

## 一键更新源码实例

桌面修改后执行 `npm run desktop:restart`，使用当前本地源码，不拉取 Git 或自动安装依赖。服务版维护执行 `npm run update`，按配置定位规则选定原实例；更新器维护服务实例的服务版入口，已知旧脚本备份到 .launcher-backup 后替换，自定义内容拒绝覆盖。

更新依次执行：有序停止并等待进程退出及端口关闭，完整备份实例目录、旧 `dist` 和包清单，核对备份文件及 SQLite 完整性／逻辑内容，执行 `npm run build`，重新启动并检查服务与网页构建一致。备份保存在源码目录 `local/updates/backup-*`，进度与结果保存在 `local/updates/last-update.json`。更新中重复点击或普通启动会被阻止；失效更新锁在原进程退出后可恢复。

备份失败立即停止，不执行构建。构建失败会恢复旧 `dist`，更新前正在运行的实例会用旧构建重新启动；不会用备份数据库覆盖日常资料。新服务启动或检查失败时保留备份并报告失败，不自动回写数据库。该入口适用于具有完整开发依赖、配置与数据位于独立实例目录的源码工作区，不拉取 Git、不自动安装依赖，也不用于只有编译产物的独立交付包。

## 配置来源与路径

正式启停、诊断、首次配置和访问码恢复共用[配置定位](../../scripts/instance-path.mjs)，按以下顺序选择配置：

1. 显式设置的 `MUSIC_APP_CONFIG`，指定文件缺失时直接失败，不回退到其他实例。
2. 产品目录已有的 `config.local.json`。
3. 产品目录位于工作区 `studio/projects/slowtune`、且配置存在时，使用与 studio 同级的 `instances/slowtune/config.local.json`；兼容既有直接位于 studio 下的源码布局。
4. 其他情况仍要求在产品目录建立 `config.local.json`；独立交付不会自动接入工作区日常实例。

前台入口会把选定路径传给正式服务；直接运行 `dist/server/index.js` 时应显式设置 `MUSIC_APP_CONFIG`。配置内的数据库、运行目录与取源可执行路径均相对该配置文件解析。数据可能位于仓库外，不能仅备份仓库就认为已备份资料。

| 字段 | 当前实现 |
| --- | --- |
| `host` | 接收 `127.0.0.1`、`0.0.0.0`、`::1`；示例默认 IPv4 回环 |
| `port` | 1–65535 的整数；示例为 4187 |
| `allowedHosts` | 非空主机白名单；启动器要求具备本机校验地址 |
| `accessKey` | 首次初始化与本机恢复使用的访问码，至少 6 字符，不能保留 `REPLACE_` 示例值；日常修改在「设置 → 启动与访问」完成 |
| `userSpace` | 本服务使用的固定用户空间 |
| `database` | 资料文件的路径前缀；歌曲资料使用该路径追加 `.song-library.sqlite`，其余 SQLite 文件追加各自后缀；当前宿主不打开原前缀文件 |
| `runtimeDirectory` | 实例控制状态、日志与加密凭据目录 |
| `mediaLeaseTtlMs` | 默认 300000；允许 85000–3600000 毫秒 |
| `ytDlp` | 可选；显式 `executable`、可选 `prefixArgs` 和 `nodeRuntime`，在启用 YouTube 后检查 |

源码：[配置校验](../../server/config.ts)、[示例](../../config.example.json)。

设置内保存的访问码以 scrypt 摘要持久化于派生设置库，后续重启沿用，不会被配置中的旧值覆盖。忘记时先停止此实例，再运行 `npm run reset-access` 恢复为配置中的 `accessKey` 并开启验证，然后重新启动。欢迎图、访问码和备份范围见[欢迎页与访问设置](../产品/启动与访问.md)。

另有 `node scripts/configure.mjs` 首次配置辅助脚本：拒绝覆盖已有文件，生成随机访问码；它当前会选择 `0.0.0.0` 并加入检测到的 IPv4 地址。只需本机使用时应按示例手动配置回环监听，避免误以为该辅助脚本默认仅本机可访问。

## 实例目录

Studio 布局将源码放在 `studio/projects/slowtune`，日常实例放在与 studio 同级的 `instances/slowtune`。配置、资料和凭据由实例维护，源码与依赖由项目维护。桌面构建位于 `studio/local/build/slowtune/desktop`，打包暂存使用同项目 build 下的 desktop-packaging，桌面交付制品归 `studio/local/artifacts/slowtune`，桌面测试与包验证归 `studio/local/runtime/slowtune`。路径声明只用于开发入口，独立交付继续使用包内资源与宿主资料位置。

| 实例内位置 | 职责 |
| --- | --- |
| `config.local.json` | 私人配置；数据库设为 `./data/library.sqlite`，运行目录设为 `./runtime` |
| `data/` | 歌曲资料库及歌词、设置、推荐、关注、浏览缓存等派生 SQLite 数据库；同步关系与待处理事件保存在歌曲资料库内，运行时的 WAL／SHM 同属对应数据库 |
| `runtime/` | B站 DPAPI 凭据、日志、当前服务状态与关闭诊断 |
| `一键启动.cmd` | 服务版入口：使用本实例配置启动服务并打开浏览器，与源码目录的桌面入口分开 |
| `桌面启动.cmd` | 桌面入口：转到源码桌面启动器，使用已有桌面构建和源码根 `data/`，不使用本实例服务配置 |
| `重建并启动桌面.cmd` | 开发刷新入口：有序退出桌面、重新构建并打开，等同 `desktop:restart`；构建失败时不打开旧版本 |

源码目录保留当前依赖与有效源码。普通服务版 `npm run build` 的 `dist`、服务更新器的 `local/updates`、更新锁及开发数据库初始化仍沿原入口维护；本次桌面路径接入不改变这些命令或数据库位置。没有路径声明的独立源码副本继续使用自身 local 桌面构建。旧目录须确认不再被使用后再清理，私人配置、数据库和凭据不复制回源码仓库。

歌词新增 `database + '.lyrics.sqlite'`，独立保存确切来源的选择、偏移及可恢复正文缓存。完整实例备份应包含该文件和对应 WAL／SHM；网页导出的歌曲资料快照不含歌词。首次使用由新构建创建歌词库，不重建既有歌曲库；网易云与 LRCLIB 请求不使用 B站 Cookie，也不要求用户配置第三方密钥。候选可用性仍取决于上游响应。

项目不保留历史构建、旧分发包、验证流水或过往备份的路径清单。当前资料由实例目录维护，项目清理不操作实例；运行验收按当前构建重新执行，要求见[验证规范](../开发/验证规范.md#当前日常实例验收)。

## 启动、复用与停止

源码目录的 `一键启动.cmd` 和实例目录的 `桌面启动.cmd` 打开独立桌面；实例目录的 `一键启动.cmd` 打开服务版。服务版维护执行 `node scripts/launch.mjs --no-open`，检查 Node、构建、依赖、配置、端口、启动锁、实例诊断和网页就绪；关闭浏览器不停止服务。

已有就绪实例且构建未陈旧时复用；陈旧实例会先尝试有序停止，等待进程结束后再启动当前构建。端口属于其他服务时明确失败。浏览器打开失败时，已就绪服务继续保留并提供手动地址。

```powershell
npm start
npm run diagnose
npm run stop
```

`npm start` 是服务前台入口，实例一键启动器也是服务版入口；源码一键启动器只打开独立桌面。服务停止与诊断根据原配置找到 service.json；现有控制脚本使用 IPv4 回环，不宣称完整 IPv6 运维支持。

服务重启后访问会话丢失，页面需要重新输入访问码。B站凭据若能被同一 Windows 用户解密则可恢复；这与浏览器访问会话分别处理。

源码：[启动器](../../scripts/launch.mjs)、[前台入口](../../scripts/start.mjs)、[控制命令](../../scripts/control.mjs)、[构建检测](../../server/build-state.ts)。

## 局域网手机使用

需要电脑服务保持运行，手机与电脑网络可达。配置监听 `0.0.0.0`，将实际局域网 IPv4 加入 `allowedHosts`，手机打开对应 `http://电脑地址:端口` 并输入访问码。防火墙和网络环境需实际检查；本项目配置并不会自动开放防火墙。

手机当前共享电脑服务中的歌单、账号和设置，队列与外观保存在手机浏览器。HTTP 访问不具备 HTTPS 的传输保护，也不能据此声称已具备原生应用安装或锁屏后台播放能力。

## 来源工具与账号

B站当前支持匿名读取及扫码登录后的对应能力；凭据使用 Windows DPAPI，绑定服务进程所在的 Windows 用户。不要把加密文件复制到另一用户／电脑就视作可迁移登录。

YouTube 默认关闭。开启时需要正确的 yt-dlp 可执行环境、前置参数与 Node JS runtime；当前交付不捆绑这些工具，不自动下载或安装。关闭时不进行工具版本探测或来源预热。设置中的“已开启”“检查中”“可用”是不同状态。

## 服务版交付

在准备好正式构建后执行：

```powershell
node scripts/package-release.mjs
```

默认输出到仓库上一级的 `local/artifacts/slowtune/slowtune-版本号-*`，脚本打印实际目标；环境变量 `MUSIC_APP_RELEASE_SOURCE`／`MUSIC_APP_RELEASE_DIRECTORY` 可另选来源／目标。

交付包含 `dist`、`vendor`、包清单与锁文件、示例配置、`项目说明.md`、`第三方声明.md`、`docs/` 及最小服务运行脚本，不额外生成 CMD 入口。它不包含私人配置、资料库、Node runtime、取源工具或已安装的 `node_modules`。打包前检查源码文档，打包后检查交付文档导航与引用。

在交付目录安装生产依赖：

```powershell
npm ci --omit=dev --ignore-scripts
```

再建立／指定配置并执行 `node scripts/launch.mjs --no-open`。无需另装 Node 的桌面交付使用 `npm run desktop:package`。交付中的源码相对链接用于开发仓库。

## 资料备份

界面 JSON 快照仅接受 slowtune-library 版本 1，用于歌曲、版本、收藏和歌单成员的追加／替换，完整范围见[产品规范](../产品/产品功能.md)。它不包括账号权限、应用关注、来源设置、推荐配置、远端同步权限、浏览器队列和音视频文件。

需要完整实例备份时，先停止该实例，再按真实配置位置备份主库、各派生 SQLite 文件与必要运行资料，包含对应 WAL 状态。`service.json`、启动锁与日志不是登录或资料的替代品。

歌曲资料备份统一为 64 MiB 限额，导入先预览并检查修订；替换须明确确认。当前没有装配远端同步执行器，不会由快照恢复触发原同步任务。接口见[接口说明](../开发/接口说明.md#新歌曲资料路由独立模块)。

网页与备份统一保存 `database + '.song-library.sqlite'`，不读取、迁移或双写原库。浏览器只采用 v3 新队列，不恢复 v1／v2；服务不接受原歌单快照格式。开发验证使用隔离配置，不自动停止或切换日常实例。

## 开发数据库初始化

新歌曲资料基础使用 [song-library-init.mjs](../../scripts/song-library-init.mjs) 初始化隔离开发库。脚本要求明确的数据库与用户空间，不读取私人配置，只接受本项目 `local/` 内的 SQLite 路径，并检查目录链接没有越界。

```powershell
node node_modules/typescript/bin/tsc -p tsconfig.server.json --outDir local/song-library-dev/dist/server
$env:MUSIC_APP_TEST_BUILD = Join-Path (Get-Location) 'local/song-library-dev'
node scripts/song-library-init.mjs --database local/song-library-dev/songs.sqlite --user-space development
```

需要重建时，向最后一条命令加入 `--reset`，删除明确指定的隔离库及其 WAL／SHM 后重新初始化。新库不接受其他表，不迁移数据或保留旧表。产品接入范围按[歌曲资料库方案](../计划/歌曲资料库方案.md)推进。

## 故障诊断

| 现象 | 检查与处理 |
| --- | --- |
| 启动提示构建缺失或页面报告版本不一致 | 在源码工作区安装依赖并完成构建，再停止／重新启动当前配置对应的实例；不要仅刷新旧服务 |
| 端口已被占用 | 运行诊断确认是否为预期实例；未知服务占用时调整端口或由其所有者处理，不直接结束未知进程 |
| Host／Origin 被拒绝 | 核对 allowedHosts、实际访问地址和同源请求；白名单填写主机名或 IP，不填写完整 URL |
| 忘记访问码 | 停止目标实例，使用访问码恢复命令，再重新启动；详细行为见启动与访问 |
| YouTube 已启用但不可用 | 核对显式工具路径与参数、Node runtime 和设置中的检查结果；开启开关不代表工具已就绪 |
| B站登录无法恢复 | 核对服务运行的 Windows 用户与 DPAPI 凭据归属；必要时重新扫码，不复制凭据冒充可迁移登录 |
| 保存冲突或导入失败 | 保留草稿与原资料，读取最新修订再核对；明确快照格式、大小和同步影响，不通过删库处理日常冲突 |
| 文档检查阻止构建 | 根据错误修复接口说明、链接或来源信息；生成区块过期时运行文档生成命令，然后重新检查 |

日志位于配置的 runtimeDirectory。按配置选择规则诊断同一实例；输出排障资料前移除访问码、Cookie、控制密钥和签名媒体地址。
